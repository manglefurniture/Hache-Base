# Reglas SEO que requieren revisión humana

No automatizar completamente estas decisiones. La automatización puede reunir evidencia, detectar patrones y proponer candidatos, pero una persona responsable debe decidir.

| Tarea | Por qué requiere juicio | Rol seguro de la automatización |
| --- | --- | --- |
| Intención de búsqueda | Una consulta puede representar tareas, etapas y audiencias distintas. | Agrupar consultas/SERPs y mostrar muestras. |
| Utilidad y satisfacción | No se reduce a longitud, legibilidad o conteo de entidades. | Detectar huecos, duplicación y feedback. |
| Experiencia de primera mano | Fotos, pruebas o biografías pueden falsificarse. | Señalar ausencia/inconsistencia. |
| Expertise | Depende del ámbito, precisión y consecuencias. | Verificar credenciales declaradas y fuentes; no puntuar E-E-A-T. |
| Originalidad | Similitud textual no prueba aporte o ausencia de él. | Comparar corpus/fuentes; revisión editorial. |
| Confianza/reputación | Contexto, gravedad y actualidad importan. | Recopilar evidencia y fechas. |
| Diferenciación competitiva | Requiere producto, marca y economía, no solo SERP. | Inventariar formatos y temas. |
| Naturalidad de anchors/copy | Reglas rígidas generan falsos positivos lingüísticos/culturales. | Detectar extremos. |
| Decisión canonical | Equivalencia semántica y objetivo de negocio pueden no ser observables automáticamente. | Señalar conflictos técnicos. |
| Redirect de contenido eliminado | Determinar un equivalente exige entender expectativa y valor histórico. | Sugerir candidatos. |
| Calidad de una landing local | Dirección, servicio, comunidad y diferencias deben ser auténticos. | Detectar clones/NAP. |
| Categorías/servicios GBP | Elegibilidad y representación real requieren decisión del operador. | Mostrar opciones y cambios. |
| Respuestas a reseñas | Privacidad, empatía y riesgo legal no admiten publicación ciega. | Borrador y triage. |
| Evaluación de enlaces | Métricas externas no determinan manipulación o valor editorial. | Priorizar patrones para investigar. |
| Declaraciones YMYL | Salud, legal, finanzas y seguridad requieren especialista y vigencia. | Detectar claims, fuentes y fechas. |
| Contenido generado por IA | Un detector no prueba autoría ni calidad. | QA factual, enlaces y duplicación. |
| Citabilidad en IA | Respuestas varían por modelo, momento, query y recuperación. | Pruebas repetidas y registro. |
| Priorización final | Impacto, alcance, riesgo y esfuerzo son del proyecto. | Calcular escenarios; responsable acepta prioridad. |

## Prohibición operativa

Ningún agente o script debe, únicamente porque una regla automática falle:

- desindexar páginas;
- cambiar `robots.txt` o canonicals de producción;
- ejecutar redirecciones masivas;
- borrar contenido;
- publicar schema o reseñas;
- comprar/adquirir enlaces;
- desautorizar enlaces.

Antes de cualquiera de esas acciones exigir: evidencia, muestra representativa, causa raíz, propietario, plan de rollback y validación posterior.
