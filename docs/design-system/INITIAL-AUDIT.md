## Método y límites

La auditoría se completó antes de modificar código. Hache Base es una caja de herramientas y no una aplicación renderizable completa: contiene un único patrón UI concreto (`backend-relief.css`) y no contiene páginas, navegación, formularios, modales, imágenes ni bundles de aplicación. Por ello, los requisitos que solo pueden verificarse sobre una instancia se clasifican `NO APLICA` en la base y se convierten, cuando corresponde, en contratos o checklist para proyectos derivados; no se inventan demos para simular cumplimiento.

Estados permitidos: `CUMPLE`, `CUMPLE PARCIALMENTE`, `NO CUMPLE`, `NO APLICA`.

## Conclusión inicial

El único bloque plenamente conforme antes de la misión es la infraestructura SEO existente. El patrón de relieve aporta una semilla útil (opt-in, foco, hover condicionado y reduced motion), pero su tokenización plana y sus estados incompletos no alcanzan la norma. La solución mínima correcta es convertir `src/ui` en un módulo separado Core/Theme/Extensions, migrar el CSS existente conservando aliases, sumar contratos/checklists donde Hache Base no posee markup real y evitar cualquier demo pesada o rediseño de marca.

La implementación no debe declarar como “probado” aquello que solo puede verificarse en un proyecto renderizado (contenido, imágenes, navegación real, formularios reales, CWV de campo o contraste de una marca concreta).
